## Система в одном абзаце

Первичные бухгалтерские документы по-прежнему вводятся в 1С. Нужные данные раз в месяц вручную копируются из стандартных форм 1С в специализированные Excel-файлы ввода, нормализуются и записываются в единую базу Access `.accdb`. Данные, которых в 1С нет в нужной детализации, вводятся в отдельных Excel-файлах. Файлы расчёта читают факты из Access, рассчитывают зарплату, налоги, амортизацию и другие показатели и записывают результаты обратно. Файлы отчёта только читают готовые данные и формируют выдачу. Основной файл Access хранит факты за все годы, справочники, регистры истории действующих значений и техническое состояние; отдельный файл Access хранит историю исправлений (технические архивы). Access не выполняет экономические расчёты.

## Компоненты

| Компонент | Читает базу | Пишет в базу | Основная задача |
|---|---:|---:|---|
| Файл ввода Excel | Да, справочники и строки для правки | Да | Принять и нормализовать исходные данные |
| Файл расчёта Excel | Да, факты и справочники | Да | Рассчитать и сохранить производный факт |
| Файл отчёта Excel | Да | Нет | Показать или напечатать готовые данные |
| База Access | — | — | Единое хранение и контроль целостности |
| 1С | Источник основной части фактов | Получает отдельные итоги вручную | Регламентированный бухгалтерский учёт |

## Ключевые действующие правила

1. Единое логическое хранилище состоит из двух файлов `.accdb`: «Учет.accdb» для рабочих данных и «ИсторияИсправлений.accdb» для технических архивов. Excel-файлы не являются постоянным хранилищем.
2. Внутренние первичные ключи создаются Access через `AutoNumber`. VBA никогда не использует `MAX(ID)+1`.
3. Для каждой таблицы определяется бизнес-ключ и, если он надёжен, уникальный индекс.
4. Внешние ключи защищаются ссылочной целостностью. Каскадное удаление и каскадное изменение запрещены.
5. Каждая логическая запись выполняется одной транзакцией DAO в общем `Workspace` для обоих файлов: рабочие изменения и архивные снимки применяются вместе либо весь пакет откатывается.
6. Попытки записи фиксируются в «Журнале операций».
7. Изменяемые строки защищены полем `Версия` и условием `ID + Версия`, чтобы не потерять чужую правку.
8. Общая `Версия данных` позволяет Power Query подтвердить согласованность составного чтения.
9. Каждый Excel-файл имеет постоянный код и версию. Access допускает только актуальные записи из таблицы «Верифицированные файлы Excel».
10. Оба файла `.accdb` защищены паролем базы. Штатные Excel-файлы хранят пароль в защищённом проекте VBA и передают его при подключении к Access.
11. Пароль открывает техническое соединение, но не заменяет проверку кода и версии Excel-файла и не считается защитой от пользователя, способного извлечь пароль из VBA.
12. Технический архив и регистр истории — разные механизмы: архив хранит ошибочно заменённые состояния, регистр истории хранит несколько законных значений для разных периодов.
13. Накопительные факты периода не заменяются фактом следующего периода; в рабочей таблице сохраняется отдельная строка каждого периода.
14. Политика исторических значений нового поля определяется отдельно по его экономическому смыслу. Фиктивные нули и пустые строки запрещены.
15. Файлы отчёта читают только рабочие таблицы, но не технические архивы.
16. Оба файла `.accdb` копируются вручную раз в неделю одним согласованным комплектом при остановленной работе и закрытых соединениях; отсутствие `.laccdb` проверяется для каждого файла.
17. Исходные блоки из 1С отдельно не сохраняются: Access хранит их нормализованное представление, практически соответствующее источнику, с вынесенными в отдельные поля счетами и субконто.
18. Перед отправкой данных из 1С формулы Excel сравнивают контрольные итоги исходного блока с итогами нормализованных строк. Любое расхождение или ошибка формулы блокирует запись в Access.
19. ОСВ загружается только полным набором за выбранный период и область отчёта. Повторная полная загрузка синхронизирует соответствующий набор в Access; отдельные состояния полноты ОСВ не ведутся. Разрешение исправлять период проверяется отдельно по общим правилам.
20. Единицей хранения данных ОСВ является календарный месяц. Квартальные и годовые итоги рассчитываются из месячных фактов и отдельно не дублируются.
21. Один рабочий рейс хранится в таблице «Рейсы», а его фактический путь — в связанных упорядоченных строках таблицы «Участки рейса».

22. Для данных, расчётов и отчётов явно описываются зависимости. При фактическом изменении система уведомляет о прямых и последующих последствиях по объектам и периодам; автоматический каскадный пересчёт не является основным режимом.
23. Централизованно задаются разрешённые и запрещённые периоды изменения. Проверяются периоды исходных и затрагиваемых зависимых данных; нарушение запрещает весь пакет, включая повторную загрузку и запись результатов.
24. Предел 2 ГБ контролируется отдельно для каждого файла; межфайловые ссылки архивов на рабочие данные и журнал проверяются программно, а не внешними ключами Access.

## Три разных вида версии

| Версия | Где хранится | Что защищает |
|---|---|---|
| Версия Excel-файла | Технический лист Excel + реестр Access | Не допускает устаревшую сборку файла |
| Версия строки | В изменяемой рабочей строке | Не позволяет перезаписать чужое изменение |
| Версия данных | В однострочной таблице «Состояние базы» | Обнаруживает изменение базы во время составного чтения Power Query |

## Правило сопровождения документации

- Новое архитектурное правило вносится в [архитектуру](Architecture/architecture.md), техническое — в [протоколы](Architecture/protocols.md).
- Причина существенного решения фиксируется новым ADR в [журнале решений](Architecture/decisions.md).
- Закрытый вопрос удаляется из [открытых вопросов](Development/open-questions.md); обоснование сохраняется в журнале решений.
- [План реализации](Development/roadmap.md) обновляется при изменении порядка работ.
- Этот обзор меняется при изменении ключевых правил или состава документов.
- [Матрица источников](Data/sources.md) дополняется при уточнении каждого контура.
- Исторический исходник на Google Drive не обновляется и не используется как источник действующих требований.
