# План реализации

Порядок работ перенесён из исходного описания. Перечисленные этапы являются планом и не подтверждают готовность реализации. Нерешённые требования находятся в [открытых вопросах](open-questions.md).

## Рекомендуемый порядок работ

### Этап A. Подготовить минимальную платформу

1. Создать «Учет.accdb» с рабочими и служебными таблицами и «ИсторияИсправлений.accdb» с техническими архивами; настроить централизованные пути к обоим файлам.
2. Настроить `AutoNumber`, связи, уникальные индексы и Validation Rules для первой предметной области.
3. Реализовать общий модуль подключения DAO и диагностики драйвера.
4. Установить пароли обоих файлов, реализовать подключение из защищённого VBA. Проверить DAO для обоих файлов и Power Query для основного файла на рабочих версиях Office.
5. Реализовать проверку версии Excel-файла.
6. Реализовать журнал, одну транзакцию общего DAO `Workspace` для обоих файлов, программную проверку ID операции в архиве, общую версию данных и обработку блокировок.
7. Реализовать общий протокол согласованного обновления Power Query.
8. Определить правила допустимых периодов и реализовать общую проверку всех штатных путей записи.
9. Спроектировать реестр зависимостей, общий механизм поиска последствий и их транзакционное сохранение с уведомлением.

### Этап B. Сделать вертикальный прототип «Рейсы»

1. Уточнить полный перечень бизнес-полей уже выбранных таблиц «Рейсы», «Участки рейса» и их технических архивов.
2. Создать файл ввода с реестром рабочих рейсов и редактором упорядоченных участков, ID и версиями строк.
3. Реализовать транзакционное создание, изменение и удаление рейса вместе с его участками.
4. Проверить конкурентную правку двумя пользователями.
5. Проверить откат рабочих изменений и архивных снимков при ошибке одной строки, недоступности архива и ошибке записи в него; отдельно проверить поведение при обрыве соединения.
6. Создать первую умную форму Access только после устойчивой работы Excel-механизма.
7. Проверить уведомления и ограничения периодов при добавлении, удалении, смене водителя, даты и участков рейса, а также при изменении расстояний.

### Этап C. Подключить данные 1С

1. Проверить реальные выгрузки ОСВ по всем счетам и по счёту.
2. Подтвердить правило уровней субконто.
3. Спроектировать окончательный бизнес-ключ Регистра бухгалтерии.
4. Реализовать листы разбора счетов, субсчетов и субконто.
5. Реализовать формулами сверку контрольных итогов исходной вставки и нормализованной таблицы; VBA блокирует отправку при любом расхождении.
6. Реализовать полную синхронизацию области ОСВ: добавление новых, обновление изменённых и архивирование с удалением исчезнувших строк.

### Этап D. Первый расчёт

1. Выбрать эталонный процесс — рекомендуется «Зарплата и налоги».
2. Определить необходимые исходные факты и регистры истории.
3. Спроектировать таблицы результата и архив.
4. Определить, будет ли печать в отдельном файле отчёта.
5. Реализовать сверку итога с 1С.
6. Описать и проверить зависимости первого расчёта и отчётов, уведомления и обработку требований пересчёта.

### Этап E. Эксплуатационный регламент

1. Ограничить сетевую папку пользователями системы и администратором, проверить создание и удаление `.laccdb`.
2. Проверить драйверы всех пользователей.
3. Зафиксировать резервного исполнителя и перенос бэкапа.
4. Определить Compact & Repair.
5. Измерить рост каждого файла на тестовом объёме и установить пороги предупреждения.
6. Проверить резервное копирование и восстановление обоих файлов одним комплектом, а также доступ и блокировки для каждого файла.
