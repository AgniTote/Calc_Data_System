# Матрица источников данных

Этот документ содержит развиваемый перечень исходных данных системы. Для каждого контура фиксируются форма данных, наличие в 1С, источник, способ загрузки, периодичность и принятое представление в Access. Новые типы данных добавляются сюда по мере обследования процессов.

## 1. Сводная матрица

| Контур данных | Форма исходных данных | Есть в 1С | Источник | Способ загрузки | Периодичность | Представление в Access |
|---|---|---:|---|---|---|---|
| Данные по счетам, субсчетам и субконто | Список строк со счётом, субсчётом, субконто, остатками на начало и конец месяца и оборотами за месяц | Да | Ручная вставка из стандартных форм 1С | Обработка ОСВ и, при необходимости, Карточки счёта | Ежемесячно | Нормализованные факты Регистра бухгалтерии за месяц и ссылки на справочники счетов, субсчетов и субконто |
| Рейсы | Один рабочий рейс с водителем, машиной, прицепом и последовательностью посещённых пунктов | Нет | Excel-файл, полученный от других сотрудников | Обработка файла ввода Excel | Ежемесячно | Две связанные таблицы: «Рейсы» и «Участки рейса» |
| Расстояния между пунктами | Расчётная таблица пар пунктов; в Excel может отображаться матрицей | Нет | Excel-файл; исходные пункты поступают от других сотрудников, расстояния рассчитываются по координатам через API OpenStreetMap | Обработка расчётного файла Excel | Ежемесячно | Список направленных пар «пункт отправления — пункт назначения — расстояние», а не матрица |

## 2. Правила по отдельным контурам

### 2.1. Данные по счетам, субсчетам и субконто

Единицей отчётного периода является календарный месяц. Каждая фактовая строка относится к конкретному месяцу и содержит суммы начального остатка, дебетового и кредитового оборота и конечного остатка. Если форма содержит количественные показатели, они хранятся по тем же правилам.

Квартал, год и произвольный диапазон не хранятся как отдельный факт: их итоги рассчитываются из месячных данных. Это делает базу универсальной и исключает одновременное хранение дублирующих месячных и квартальных сумм.

Основным источником является ОСВ. Карточка счёта используется только там, где ОСВ не содержит необходимой детализации. Требования к структуре и контролю полноты Карточки счёта проектируются отдельно.

### 2.2. Рейсы

Одна строка таблицы «Рейсы» соответствует **одному рабочему рейсу**, то есть законченной хозяйственной работе, которую пользователь воспринимает и рассчитывает как единое целое. Например, рабочим рейсом может быть доставка `Мастерстрой → ТКЗ`.

Физическое движение хранится в связанной таблице «Участки рейса» с порядковым номером:

| ID рейса | № участка | Откуда | Куда |
|---:|---:|---|---|
| 125 | 1 | База | Мастерстрой |
| 125 | 2 | Мастерстрой | ТКЗ |
| 125 | 3 | ТКЗ | База |

Такой подход позволяет одновременно:

- считать оплату или результат по рабочему рейсу;
- рассчитывать полный пробег по всем физическим участкам;
- сохранять возвраты на базу и промежуточные точки;
- не дублировать водителя, машину, прицеп и другие общие свойства в каждой части маршрута.

Минимальная структура основной записи пока включает дату или период рейса, водителя, машину и допускающий `Null` прицеп. Полный перечень свойств и бизнес-правила будут определены при проектировании вертикального прототипа «Рейсы».

Связь таблиц имеет вид «один рейс — много участков». Участок обязательно ссылается на существующий рейс, а сочетание `ID рейса + № участка` уникально. Рейс и весь его маршрут находятся в основном файле «Учет.accdb». Для прежних состояний предусмотрены таблицы «Рейсы архив» и «Участки рейса архив» в отдельном файле «ИсторияИсправлений.accdb». Рабочие изменения и архивные снимки записываются одной транзакцией общего DAO `Workspace` для обоих файлов.

### 2.3. Расстояния между пунктами

Матрица удобна для просмотра и расчёта в Excel, но в Access данные хранятся построчно: одна запись соответствует одной направленной паре пунктов.

Пара считается направленной, потому что расстояние `A → B` потенциально может отличаться от `B → A` из-за дорожной сети и правил движения. Предварительный бизнес-ключ: `ID пункта отправления + ID пункта назначения`. Вместе с расстоянием следует хранить дату расчёта и, при возможности, версию или профиль маршрутизации API, чтобы результат можно было обновлять контролируемо.

Ежемесячная обработка файла не означает обязательный пересчёт всех существующих пар. Файл может добавлять новые пары и обновлять повторно рассчитанные пары; точное правило полной или частичной синхронизации будет определено отдельно.

## 3. Статус заполнения

Матрица начата и не считается окончательной. Следующие типы данных добавляются по мере их определения. Наличие строки в матрице фиксирует контур и исходный поток, но не означает, что все таблицы, поля, бизнес-ключи и правила готовности уже спроектированы.
